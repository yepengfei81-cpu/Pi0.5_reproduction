# 任务采集/部署协议(单一真源)

> 每个任务的机械臂起始分支、场景设定、随机化范围。**采集和 rollout 必须同协议**。
> 为什么 J4 分支必须钉死: 我们的 state 是 W' 末端位姿(无关节角), ±90° 两个分支在模型
> 眼里是同一个观测——混采 = 不可观测的模式噪声; 且错误分支会在任务中段撞关节限位
> (运动学事实, 策略学不会绕开)。分支由 lead 决定(follow 对齐 lead), 部署用
> --start-from-lead 复现同一分支。

## J4 分支与关节限位(2026-09-13 数据实测)

- **抽屉在原 +90° 分支下, J4 全程落在 [+60°, +172°]**: 平行爪 50 条里 31 条顶到 J4 上限
  (follow 固件软限位 +171.9°), 41 条手腕余量 <5°; 开顶层、中段、放第三层都会顶。J4/J6 是
  手腕滚转关节, 部署时笛卡尔 IK 在限位附近可能换解 —— 这是抽屉 rollout "突然跳一下"的最可能原因。
  其他任务 J4 都在 ±150° 以内。
- **换 −90° 分支后 50 条全部留在行程内**(手腕最小余量中位 23°, 最差 14°)。
- **为什么已采的 50 条 +90° 数据不用重采**: 两个分支是严格的手腕等价解
  (关节**读数**上是 J4−180°, J5 取反, J6+180°; **物理操作只转 J4, 夹爪和手眼相机朝向保持不动**,
  J6 读数的 180° 变化是 J4 转过去后自动产生的, 不是去转相机), URDF 正运动学核对末端位姿差 0.002 mm / 0.0006°;
  真机数据里已有大量这类帧对(如 J4 +81/J5 −1/J6 −84 与 J4 −95/J5 +4/J6 +94, 夹爪朝向差 1.3°); 模型只看
  W' 末端位姿和腕相机(装在 J6 之后, 位姿也相同), 所以训练数据完全一致。唯一差别是环境相机里
  前臂/腕部连杆的外观。严格跨爪配对的话, 平行爪抽屉日后可在 −90° 下补采一批替换。
- **规则**: GET 抽屉按 −90° 采; 抽屉部署 `--start-from-lead` 时 lead 也摆在 −90°(IK 会沿当前分支继续)。
- J2 顶上限止挡(积木/金字塔/擦黑板几乎每条都有)只限制够远, 部署无害, 不需要改协议。
- 采集脚本默认开启关节守卫(`collect_data.py --joint-margin 15`, 0=关闭), 部署用 `local_inference_eef.py --log-joints`。

## 全局场景常量(所有任务)

- **操作区垫板必须在位**: 全部历史数据(550条)都是带板采集的, 模型把板边缘当空间基准
  (W' 相对系下视觉是唯一的全局定位来源)——去板 rollout 已实测 OOD(金字塔最明显)。
  部署与采集都必须带板; 若未来要板无关, 需从采集期就逐条随机化台面, 不能事后补一小批。

## 开录检查单(每条 episode 按 Enter 前)

1. **lead 臂 J4 在本任务的分支上**(查上表)——follow 会对齐 lead, 分支由 lead 决定;
2. 场景摆放符合上表(刀刃朝左 / 杯把手朝向已随机 等);
3. 本条的随机化已做(物体位置/开局位姿, 别整批一个位置);
4. 首条试录后检查 `telemetry/episode_000000.npz` 存在且行数≈时长×100;
5. **录完看关节守卫小结**(问"保存本条?"之前那行): `⛔ 手腕关节顶限位` → 本条数据仍可存(末端轨迹有效),
   但要调整下一条的开局/物体摆位; 同一任务连续出现 → 该任务的 J4 分支要重新评估(参照上节抽屉的分析)。

## 示教纪律

- 松爪/释放动作**干脆果断**(犹豫会被模型克隆成拖延);
- 失败/卡限位/明显挣扎的条目直接 `d` 丢弃;
- 每次采集会话保持同一协议, 改协议 = 换 prompt 或另开数据集。

## 部署对应

- rollout 用 `--start-from-lead`, **lead 摆到上表的分支+示教开局姿态**;
- prompt 与上表逐字一致。
