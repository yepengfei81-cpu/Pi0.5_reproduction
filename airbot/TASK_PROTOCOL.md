# 任务采集/部署协议(单一真源)

> 每个任务的机械臂起始分支、场景设定、随机化范围。**采集和 rollout 必须同协议**。
> 为什么 J4 分支必须钉死: 我们的 state 是 W' 末端位姿(无关节角), ±90° 两个分支在模型
> 眼里是同一个观测——混采 = 不可观测的模式噪声; 且错误分支会在任务中段撞关节限位
> (运动学事实, 策略学不会绕开)。分支由 lead 决定(follow 对齐 lead), 部署用
> --start-from-lead 复现同一分支。

## 全局场景常量(所有任务)

- **操作区垫板必须在位**: 全部历史数据(550条)都是带板采集的, 模型把板边缘当空间基准
  (W' 相对系下视觉是唯一的全局定位来源)——去板 rollout 已实测 OOD(金字塔最明显)。
  部署与采集都必须带板; 若未来要板无关, 需从采集期就逐条随机化台面, 不能事后补一小批。

## 开录检查单(每条 episode 按 Enter 前)

1. **lead 臂 J4 在本任务的分支上**(查上表)——follow 会对齐 lead, 分支由 lead 决定;
2. 场景摆放符合上表(刀刃朝左 / 杯把手朝向已随机 等);
3. 本条的随机化已做(物体位置/开局位姿, 别整批一个位置);
4. 首条试录后检查 `telemetry/episode_000000.npz` 存在且行数≈时长×100。

## 示教纪律

- 松爪/释放动作**干脆果断**(犹豫会被模型克隆成拖延);
- 失败/卡限位/明显挣扎的条目直接 `d` 丢弃;
- 每次采集会话保持同一协议, 改协议 = 换 prompt 或另开数据集。

## 部署对应

- rollout 用 `--start-from-lead`, **lead 摆到上表的分支+示教开局姿态**;
- prompt 与上表逐字一致。
