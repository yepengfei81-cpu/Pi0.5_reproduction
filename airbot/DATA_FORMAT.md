# Raw recording format / 原始采集数据格式(新机械臂接入必读)

This is the exact format every teleoperation collector in this repo writes
(`airbot/collect_data.py` for AIRBOT Play, `airbot/collect_data_yam.py` for YAM).
A collector for any other arm must produce the same thing; the packer
`umi/pack_lerobot_fast.py` then turns it into the 20-D training dataset
described in README §1 without caring which arm it came from.

本仓库所有遥操作采集脚本写出的格式完全一致;新接一种机械臂只要产出同样的东西,
打包脚本 `umi/pack_lerobot_fast.py` 就能把它和其他臂的数据合成同一个 20 维训练集。

## 1. Directory layout / 目录结构

One LeRobot v2.1 dataset per collection session (`LeRobotDataset.create(...)`, fps = 10):

```
<output-dir>/<repo-id>/
  meta/info.json            features, fps=10, total_episodes, total_frames
  meta/episodes.jsonl       one line per episode (length, tasks)
  meta/tasks.jsonl          {"task_index": 0, "task": "<prompt, verbatim>"}
  data/chunk-000/episode_000000.parquet      per-frame table (columns below)
  videos/chunk-000/image/episode_000000.mp4         environment camera
  videos/chunk-000/wrist_image/episode_000000.mp4   wrist camera (arm 0)
  videos/chunk-000/wrist_image_1/episode_000000.mp4 wrist camera (arm 1, dual-arm only)
  telemetry/episode_000000.npz               100 Hz sidecar (optional but recorded by default)
```

If a dataset with the same `repo-id` already exists the collector appends a
timestamp to the name; the packer merges any number of such directories.

## 2. Per-frame columns / 每帧列(10 Hz)

Single-arm collection (`collect_data.py` without `--dual-arm`, `collect_data_yam.py`):

| Column | Shape | Content |
|---|---|---|
| `image` | 480×640×3 uint8 (stored as H.264 video) | environment camera, RGB |
| `wrist_image` | 480×640×3 | wrist camera on the gripper, RGB |
| `state` | 7 float32 | follower joint angles (6, rad) + gripper reading (1) |
| `actions` | 7 float32 | leader joint angles (6, rad) + gripper command (1) |
| `state_eef` | 8 float32 | follower end-effector pose in the arm **base frame**: `x y z` (m) + quaternion `qx qy qz qw` + gripper reading |
| `actions_eef` | 8 float32 | leader (commanded) end-effector pose, same layout, + gripper command |
| `task_index`, `timestamp`, `frame_index`, `episode_index`, `index` | | LeRobot bookkeeping (written by `add_frame` / `save_episode`) |

Dual-arm collection writes `wrist_image_1`, `state_eef_0/1`, `actions_eef_0/1`
instead (no joint columns); the packer handles both.

**Only `state_eef` / `actions_eef` (and the videos, task) are used by the
packer.** `state`/`actions` (joint space) are kept for analysis and so that the
end-effector columns can be regenerated offline with a corrected kinematic model.

## 3. Conventions the packer relies on / 打包脚本依赖的约定

These must hold for every arm, otherwise its data is incompatible with the rest.

1. **Pose = the arm's reference point (ARP), not the fingertip.**
   On AIRBOT Play, `get_end_pose` reports the fingertip of the factory parallel
   gripper (73.5 mm in front of the mounting face), whichever gripper is mounted.
   For another arm, define the reported point so that the mounted gripper's
   fingertip is at the same place relative to it as on AIRBOT (for GET: fingertip
   = ARP + 17 mm along the approach axis). `collect_data_yam.py --tool-offset`
   does this. The packer's `--arm-frame` mode (the current default) then adds
   **no** tool offset; the gripper's reach is carried by its point cloud.
2. **Tool-frame axes:** +X = approach direction (pointing out of the fingers),
   +Y = gripper opening axis, +Z = up when the gripper is horizontal.
   Rotation is stored as a quaternion `xyzw` of this frame in the base frame.
   Base frame: z up (gravity-aligned); x/y arbitrary (the packer removes the
   first-frame yaw and position by building a per-episode frame W′).
3. **Gripper value:** stored in whatever units the arm reports, but **the
   same units in `state_eef[7]` and `actions_eef[7]`**. The packer normalises
   with the `close`/`open` values registered for the gripper name in
   `gripper_geom/gripper_params.py` (0 = closed, 1 = open). The YAM collector
   normalises before saving, so its entry (`get_yam`) is `close=0, open=1`.
4. **Action gripper = leader command, not follower reading** (the follower
   reading stops at the object width and cannot express squeezing). The pose
   part of the action is regenerated by the packer from the next frame's
   `state_eef`; `actions_eef`'s pose is currently not used for training.
5. **Frames are 10 Hz** (`fps` in `info.json` must be 10) and the control loop
   should be ~100 Hz with the 10 Hz record happening on every 10th tick.
6. **Prompt:** `--task` string, verbatim; the same string is used at deployment.
7. Camera videos: 640×480, H.264, 10 fps, written by LeRobot's video writer
   (RGB in, the packer copies the files byte-for-byte).

## 4. Telemetry sidecar / 遥测文件(可选)

`telemetry/episode_XXXXXX.npz`, float32 arrays of length N (~100 Hz):
`t` (s since episode start), `frame_idx` (how many 10 Hz frames had been
recorded when this row was taken), `cmd_q [N,6]` leader joints, `cmd_grip [N]`,
`q [N,6]` follower joints, `dq [N,6]`, `tau [N,6]` joint torque/current,
`grip_q [N]`, `grip_tau [N]`. Dual-arm files suffix every array with `_0`/`_1`.
Missing telemetry is fine (the packer writes zeros + `effort_mask=0`).

## 5. Registering a new arm or gripper / 新臂、新爪要改的地方

- A new **gripper**: add `gripper_geom/gripper_params.py[<name>]` (`close`, `open`,
  `tcp_offset`), add `<name>_points/_region/_finger` to `gripper_geom/grippers_armframe.npz`
  (`align_to_arm_frame.py`), list the name in the packer's `--gripper-names` and
  the training config's `gripper_names` **in the same order** (the index is the
  `gripper_id` stored in the packed data).
- A new **arm** needs only a collector producing the format above with the
  conventions in §3; nothing else in the pipeline refers to the arm.
  `collect_data_yam.py` is the reference implementation (forward kinematics
  embedded from the arm's URDF, tool frame re-expressed to the convention above).

## 6. Quick self-check / 自检

```bash
python umi/pack_lerobot_fast.py --arm-frame --template <any packed 20-D dataset> \
  --teleop-dir <new dataset dir> --teleop-gripper <gripper name> \
  --gripper-names parallel get <gripper name> --repo-id check -o /tmp/check --verify
```
`--verify` reloads the output and prints `state[0]`; arm 0 should start at
`[0,0,0, 1,0,0, 0,1,0, g]` (W′ origin, identity rotation) and the gripper
value should move between 0 and 1 across the episode.
